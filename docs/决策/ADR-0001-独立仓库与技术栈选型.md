# ADR-0001：独立仓库与技术栈选型

- 状态：已确认
- 日期：2026-07-28
- 相关：cc-trace 的 [ADR-0002](https://github.com/nanvon/cc-trace/blob/main/docs/决策/ADR-0002-首版单应用结构.md)、[ADR-0016](https://github.com/nanvon/cc-trace/blob/main/docs/决策/ADR-0016-不购买Apple开发者账号.md)

## 背景

CC Trace 桌面端第 11、12 阶段进行中，移动端此前不在产品范围内——`docs/产品范围.md` 的四个列表都没有提到它。本次决定启动移动端，需要先确定它和桌面端的关系。

cc-bar 参考资料里的 [10-移动端获取 Codex 与 Claude 用量](https://github.com/nanvon/cc-trace/blob/main/docs/cc-bar-reference/10-移动端获取%20Codex%20与%20Claude%20用量.md) 曾推演过移动端方向，但那是对 Nowdex 安装包**静态字符串**的观察，证据等级最低。

## 决策

### 1. 独立仓库，不并入 cc-trace

`cc-trace-mobile` 是独立仓库，不与桌面端组成 monorepo。

### 2. 技术栈：Tauri 2 Mobile + Vue 3 + Rust

一套代码同时出 iOS 和 Android。

### 3. 沿用桌面端的语义，不沿用桌面端的代码

| 沿用 | 不沿用 |
|---|---|
| 三维状态契约（活动 / 快照新鲜度 / 失败原因） | 凭据发现（手机上不存在本机凭据文件） |
| 设计 token、余量四档色、状态表达 | 紧凑面板布局与尺寸 |
| Provider 响应解析与额度归一化 | 桌面壳、Tray、窗口生命周期 |
| 「不显示伪造 0%」等业务规则 | 调度与退避的具体参数基线 |

### 4. 接口事实的来源是桌面端已验证的实现

Provider 接口路径、字段解析、归一化规则以 cc-trace 的 `docs/额度领域模型.md` 和 `src-tauri/src/providers/` 为准——桌面端已于 2026-07-27 在 macOS 完成真实数据验证。

10 号参考文档**只在 OAuth 一节**具备不可替代价值，因为桌面端不做登录。其余内容不得作为接口依据。

## 理由

### 为什么独立仓库

移动端和桌面端的**凭据来源、授权模型、刷新调度、分发渠道全部不同**。桌面端读本机 `~/.codex`、`~/.claude`；移动端一行都读不到，必须自建 OAuth 登录——而「应用内 Provider 登录」恰恰是桌面端 `docs/产品范围.md` 明确不做的一条。

真正可共享的只有 Provider 响应解析和额度归一化，约几百行，且其正确性本来就靠脱敏 fixture 保障，复制的维护成本可控。

共享收益 < 耦合成本。更重要的是：桌面端契约仍在收敛，Windows 侧从未实机验证过，把两端绑进同一个仓库会让桌面端的每次改动都被迫考虑移动端。

这同时满足 cc-trace ADR-0002 的复审条件「出现第二个应用入口」——复审结论是**拆开**，不是升级成 monorepo。

### 为什么 Tauri 2 Mobile

目标平台是 iOS + Android 两个。原生方案（SwiftUI / Kotlin）意味着同样的逻辑写两遍，而这个产品的业务逻辑（OAuth、额度归一化、状态机）恰恰是两端完全一致的部分。

Tauri 2 还能让 Rust 侧的 Provider 解析和 Vue 侧的设计 token 直接从桌面端搬过来。

代价（已知并接受）：Tauri 移动端生态成熟度低于桌面端，OAuth 回调、安全存储（Keychain / Keystore）、后台刷新大概率需要插件或自写。

## 替代方案

| 方案 | 不采用的原因 |
|---|---|
| 并入 cc-trace 做 monorepo | 共享面只有解析层，却要让收敛中的桌面端承担耦合成本 |
| 原生 SwiftUI（仅 iOS） | 目标是双平台；且 ADR-0016 下 iOS 反而是最难分发的那个 |
| 原生 Kotlin（仅 Android） | 同上，放弃 iOS 不符合目标 |
| 桌面端生成脱敏摘要同步给手机 | 需要跨设备同步协议，是另一个产品能力，且要求桌面端常开 |

## 后果

- Provider 解析代码在两个仓库各有一份。上游字段变化时**两边都要改**，靠各自的 fixture 测试兜底。若日后维护成本变高，再抽成独立 crate。
- **iOS 无法上架。** 继承 cc-trace ADR-0016（不购买 Apple 开发者账号），免费 Apple ID 只能真机签名 7 天。iOS 侧首版定位为自用；Android 可直接分发 APK。
- 「应用内 OAuth 登录」在桌面端是明确不做项，在移动端是必须项。两端的产品范围文档必须各自独立，不得互相引用该条。

## 复审条件

- [OAuth 可行性验证](../OAuth可行性验证.md)结论为不可行——届时整个技术选型和产品形态都要重新考虑。
- Provider 解析代码的双份维护成本明显上升。
- ADR-0016 被推翻（购买 Apple 开发者账号），iOS 分发路径改变。
