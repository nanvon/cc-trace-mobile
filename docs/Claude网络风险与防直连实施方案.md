## 1. 结论与目标

**Android 的 Claude 刷新默认使用当前 VPN。** 用量、账号资料和 token 续期需要 VPN 覆盖应用，
且 VPN 路由覆盖 DNS 和目标地址。请求绑定该 VPN，失败时保留快照并按现有退避重试。
用户可以沿用已有的 mihomo 规则。代理客户端仍决定实际出口。

首次网页登录和授权码交换仍走现有登录链路。请求失败、超时、界面显示网络错误，都不能证明
服务端此前没有收到连接或请求。HTTPS 保护传输内容，服务端仍能看到来源 IP。

拟实现的技术目标是：**网络保护条件不满足时，不启动 Claude 应用内远程请求，不退回直连，
保留本地快照并说明暂停原因。** 外部浏览器登录另需系统级网络保护。

这个目标只能减少意外直连，不能承诺避免封号，不能消除地区政策和第三方 OAuth 使用限制。
不应把功能命名为“防封号”或显示“账号安全”“保证境外出口”等无法证明的状态。

### 2.1 地区限制

Anthropic 当前地区政策生效日期为 2026-11-12，中国大陆不在支持名单中；政策明确涵盖人在

- [Supported Regions Policy](https://www.anthropic.com/legal/supported-regions)
- [Safeguards warnings and appeals](https://support.claude.com/en/articles/8241253-safeguards-warnings-and-appeals)

官方说明存在因不支持地区注册、服务条款或使用政策违规而封禁的情况。本次未找到“一次中国
IP 请求就必定封号”的官方规则，也未找到某类代理、住宅 IP、固定节点保证不封号的承诺。
不得编造封号概率、检测阈值或“安全请求间隔”。

### 2.2 独立于网络的 OAuth 风险

[Claude Code 官方认证使用限制](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use)
说明 OAuth 面向原生 Anthropic 应用的正常使用，并限制第三方开发者在自己的应用中提供
Claude.ai 登录。

本项目当前复用官方 CLI 的 OAuth Client ID，由本应用交换和保存 token；未找到只读订阅用量
工具获准例外的明确官方说明。这是需要单独解决的产品风险，不能通过网络防护消除，也不能
因为只查询额度、接口可以调用就认定获准使用。

建议在继续公开分发该登录能力前确认官方允许的接入方式。这个建议不是本次授权删除或停用
Claude 功能，也不是对具体账号是否会被处罚的判断。API Key 能否取得相同的 Pro/Max 订阅
用量，本次没有证据；不得直接替换认证方式并声称能力等价。

### 3.1 Dart HTTP、系统代理与 VPN 的关系

移动端 `http.Client()` 默认创建 `IOClient`，后者默认创建 Dart `HttpClient`。未设置
`findProxy` 时，Dart 层直接建立目标连接。系统 VPN/TUN 仍可接管该连接，所以“Dart 直连”
不等于“必然绕过系统 VPN”；但也不能推断它自动遵从浏览器代理或 Wi-Fi HTTP 代理配置。

- [http.Client 工厂](https://pub.dev/documentation/http/latest/http/Client/Client.html)
- [IOClient 构造](https://pub.dev/documentation/http/latest/io_client/IOClient/IOClient.html)
- [HttpClient.findProxy](https://api.dart.dev/dart-io/HttpClient/findProxy.html)

### 3.2 必须覆盖的 Claude 请求链路

真实端点以 `lib/auth/oauth_config.dart` 为准，本次基线为：

| 用途 | 地址 | 发起方 |
|---|---|---|
| 授权登录初始页 | `https://claude.com/cai/oauth/authorize` | Android 浏览器 |
| 授权码交换、刷新 token | `https://platform.claude.com/v1/oauth/token` | `OAuthCoordinator` / `ProviderApi` |
| 查询用量 | `https://api.anthropic.com/api/oauth/usage` | `ProviderApi` |
| 补全账号与套餐 | `https://api.anthropic.com/api/oauth/profile` | `ProviderApi` |

`_fetchWithToken` 会并行查询用量和必要的 profile；profile 已完整时跳过。登录网页的重定向、
资源域名未枚举，不能把表中域名宣称为浏览器完整清单。

`localhost`、`127.0.0.1`、`::1` 是 OAuth 本机回调，不能发往远程代理。Q3 的 synthetic
callback 只访问本机，和打开真实授权页的风险不同。

### 3.3 已有能力与缺口

保留现有：HTTPS、PKCE/state、安全凭据存储、账号代次防迟到写入、同 Provider 请求合并、
15 秒超时取消、手动刷新 10 秒节流、429/网络错误退避，以及失败时保留旧快照。
网络错误退避为 30/60/120/300 秒；429 本地退避为 60/120/300/900 秒，并尊重更长的
`Retry-After`。这不是官方认可的“防封禁频率”。

已有测试包含超时断开、代理错误页面、407、TLS 失败、凭据刷新和调度等场景；没有据此验证
Android 系统 VPN 或 mihomo 断线时不会直连。本次没有运行这些测试。

## 4. 故障情形与保护责任

| 情形 | 当前结果 | 所需保护 |
|---|---|---|
| 忘记开代理后打开应用 | 到期可能自动请求 | 系统阻断 + 应用强制代理 |
| VPN 仍运行但节点断开 | 无直连路由时通常失败，取决于客户端配置 | mihomo 不允许 DIRECT 回退 |
| VPN 退出，系统恢复普通网络 | 后续请求可能直连 | Android 阻止未使用 VPN 的连接 |
| 应用或浏览器被排除出 VPN | 可能走普通网络；系统阻断启用时可能无网络 | 核对两个应用的分应用配置 |
| mihomo 内部规则选择 DIRECT | 流量即使进入 VPN 也可能被直连转发 | 核对规则顺序、代理组、嵌套组 |
| Wi-Fi/蜂窝切换或重连 | 无专门暂停机制 | 失效即取消和暂停，恢复后重新判断 |
| 用量受保护，token/profile 未受保护 | 仍有带凭据请求风险 | 所有 Claude 应用内端点统一保护 |
| 只给应用配置代理 | 外部浏览器仍独立联网 | 浏览器由系统级保护覆盖 |
| 先查询 IP 再访问 Claude | 两个域名可能不同出口；检测后网络可变化 | IP 检测仅作诊断 |

“VPN 已连接”“代理端口存在”“某网站显示境外 IP”都不能证明 Claude 必然经过预期远程出口。
已经发出的请求无法撤回；检测到断线后取消只能减少后续活动，不能替代传输层与系统阻断。

## 5. 首次调查提出的备选方案

后续实施选择使用 Android 提供的 VPN 网络绑定，用户无需在 CC Trace 中填本机代理端口。
以下手动代理、持久暂停和浏览器保护是首次调查的建议，均超出本次刷新保护的范围。

推荐组合：**Android 系统断线阻断 + mihomo 无直连规则 + 应用内强制代理与持久暂停。**
这是一项建议，尚未获得产品实现授权。

### 5.1 Android 与 mihomo 配置

由用户在支持该能力的客户端上启用系统“始终开启 VPN”和“阻止未使用 VPN 的连接”。
仅启用前者不代表会阻止直连。CC Trace 包名是 `com.nanvon.cctrace.mobile`，授权浏览器也
必须纳入保护。系统阻断可能影响其他被排除的应用，不能擅自替用户修改。

系统阻断约束普通应用绕过 VPN 的连接，不保证 mihomo 内部选用远程代理；客户端自己处理的
DIRECT 出站仍需配置约束。Claude 相关规则应优先于可能命中的直连规则，核对所有引用的代理
组与回退链，不包含 DIRECT。节点失败时允许请求失败，不能以“恢复可用”为由改为直连。

- [Android：阻止非 VPN 连接、分应用列表及绕过行为](https://developer.android.com/develop/connectivity/vpn)
- [mihomo：规则按从上到下匹配](https://wiki.metacubex.one/config/rules/)
- [mihomo：fallback 按顺序选可用节点](https://wiki.metacubex.one/config/proxy-groups/fallback/)

### 5.2 应用内强制代理

若目标客户端开放本机 HTTP 或 mixed 端口，建议 Claude 应用内 HTTPS 请求通过该端口建立
CONNECT 隧道，并保留正常 TLS 证书校验。代理不可达、拒绝认证或失败时停止，不建立目标
直连。Dart 的代理配置不得包含 `; DIRECT`，异常处理不得创建默认客户端重试。

只支持已核实的端口协议。Dart `findProxy` 的 HTTP 代理不能直接套用 SOCKS 端口。
优先使用回环地址；不要因本机访问而开启 LAN 共享，也不要假定端口固定为 7890。
[mihomo 端口说明](https://wiki.metacubex.one/config/inbound/port/)。

此方案能约束应用的下一跳为本机代理，不能证明本机代理最终使用的出口。外部浏览器不会
继承该配置；如果无法确认浏览器系统保护，应阻止从应用发起新的 Claude 登录，而不能显示
“登录已受保护”。已有浏览器页面也不能保证被应用彻底关闭或停止联网。

### 5.3 实施前必须明确的输入

| 未确认项 | 推荐选择或核对方式 | 未确认的影响 |
|---|---|---|
| Android 版本、代理客户端名称及版本 | 用户提供，核对客户端官方说明与实际设置 | 无法保证 always-on/阻断/本机端口能力 |
| 本机代理协议与端口 | 使用用户确认的 loopback HTTP/mixed 端口 | 不能硬编码端口、静默扫描或退回直连 |
| 新安装与老用户升级的保护默认值 | 建议 Claude 默认保护；未配置时只显示缓存并阻止联网 | 会改变现有启动、自动刷新和登录行为，需明确采纳 |
| 外部浏览器保护条件如何确认 | 系统阻断配置 + 真机验收；用户确认仅为配置声明 | 普通应用不能仅凭 VPN 状态证明整个浏览器链路安全 |
| 恢复策略 | 建议用户主动暂停后仅手动恢复；临时网络异常在保护重新就绪后按原调度恢复 | 避免自动解除用户暂停或无限重试 |
| 状态模型扩展 | 沿用三维契约，明确暂停、保护未就绪与地区/权限拒绝的表达 | 影响枚举、序列化、UI、测试，不能只改提示文字 |
| 第三方 OAuth 使用边界 | 单独确认官方允许方式及后续产品取舍 | 网络改造不解决接入政策风险 |

不要把这些待确认事项当作已经通过的 ADR。后续用户明确授权整套方案时，按授权范围执行，
不逐文件重复索取同一授权；确需扩大范围或推翻既有决策时再说明原因。

- [ ] 扩展取消语义时区分超时与用户/保护取消；现有 helper 会把 abort 统一转成 TimeoutException，不能照搬。

### T3：登录浏览器、Debug 入口与界面

- [ ] 检查 `signIn`、`reopenBrowser`、浏览器选择后真正打开页面前，以及 Q3 真实授权入口。
- [ ] 回调到来后的 token 交换重新受 T1 保护，不沿用打开浏览器时的旧判断。
- [ ] 保护失效时结束应用自己的登录等待；不要声称已阻止浏览器全部后台流量。
- [ ] 保留回环回调、PKCE、state 和 Android Intent 校验，不把本机回调代理到远程。
- [ ] 界面明确显示“已暂停 Claude 联网”或“网络保护未就绪”，并展示缓存时间。
- [ ] 无保护时“刷新”“重新登录”“换浏览器”等操作也不能绕过；避免只禁用一个按钮。
- [ ] 不继续复用“网络恢复后会自动重试”文案描述用户主动暂停；不提示必须重新登录来解除保护。

完成条件：所有正式和 Debug 登录入口遵守相同边界；外部浏览器仍明确依赖系统保护。

### T4：保守处理 403 与诊断

- [ ] 读取真实脱敏响应或官方错误契约后再分类，不猜地区/账号限制的字段和值。
- [ ] 不再把所有 JSON 403 视为 token 失效。明确地区/账号策略拒绝应暂停自动尝试，不能自动刷新 token。
- [ ] 未识别的 403 采用保守的拒绝状态和显式恢复，不伪称已确认封号，也不强推重新登录。
- [ ] 保留真正认证失效的正常处理；不得把所有 401/403 都解释成地区限制。
- [ ] 仅记 Provider、阶段、阻止原因、状态码、取消原因等安全字段。
- [ ] 不写 token、code、完整授权 URL、响应体、代理密码、订阅链接或完整公网 IP 到诊断日志。

完成条件：状态分类、调度、UI 和测试一致，代理错误不会被冒充为封号，策略拒绝不会触发盲目重试。

## 7. 验证计划与通过标准

本节全部是待执行计划。本次未运行测试；本文不授权自动运行耗时命令、操作手机、抓包或
使用真实账号。后续遵守用户对编译、测试和设备操作的授权范围。

### 7.1 定向自动化验证

应验证行为与实际传输，不只断言代理字符串或界面文字：

| 验证项 | 通过标准 |
|---|---|
| 代理未启动、拒绝或中途断开 | 不建立目标直连，失败不回退默认客户端 |
| 测试代理正常 | 请求经过代理；TLS 目标校验仍有效；目标域名交由 CONNECT 处理 |
| 用量/profile/token 交换/token 刷新 | 所有远程出口同样受保护，重试和重定向无旁路 |
| 暂停与旧设置迁移 | 启动、手动、自动、回前台、重启都符合约定默认值 |
| 配置修改/取消与迟到响应 | 无旧状态覆盖、无后续请求；凭据轮换不会被错误覆盖或静默破坏 |
| 401/403/429 | 分类准确，禁止盲目 token refresh，保留限流退避 |
| 双 Provider | Claude 暂停或关闭连接不影响 Codex |
| 浏览器与 Q3 | 不满足登录条件时不调用 browser.open；回调后的交换再检查 |
| 诊断 | 可以定位阻止原因，不泄露凭据与个人网络信息 |

优先扩展现有 `test/abortable_http_test.dart`、`test/provider_api_test.dart`、
`test/oauth_test.dart`、`test/app_controller_test.dart`、`test/storage_models_test.dart`、
`test/usage_screen_test.dart`、`test/browser_bridge_test.dart`、`test/diagnostics_test.dart`。
有必要时新增本地代理传输测试；仅用合成凭据和本地测试服务器，不访问真实 Claude。

获得测试授权后，可按改动范围运行，例如：

```sh
flutter test test/abortable_http_test.dart test/provider_api_test.dart test/oauth_test.dart test/app_controller_test.dart test/storage_models_test.dart
```

这条命令不包含所有 UI、浏览器和诊断测试，也不自动包含未来新增文件；执行者应根据最终
改动补充具体文件。`git diff --check` 只检查补丁格式，不是编译或测试。代码实施后按仓库
规则做必要的简单编译检查；完整 lint、构建、测试或设备验收需要相应授权，不能擅自扩大。

### 7.2 Android 真机矩阵

用不带真实凭据的自有测试目标先验证传输约束，不要通过故意让真实 Claude 账号直连来测试
是否会封号。网络约束确认后，再由用户决定是否进行真实 Provider 验收。

| 编号 | 场景 | 应观察的结果 |
|---|---|---|
| A1 | 开机或冷启动，代理尚未启动 | Claude 应用内请求停止；系统阻止浏览器普通联网 |
| A2 | 代理进程退出或 VPN 断开 | 无新的 Claude 目标直连；应用取消/暂停并显示缓存 |
| A3 | VPN 存在，但远程节点不可用 | 失败，不选 DIRECT，不持续刷新 token |
| A4 | Wi-Fi → 蜂窝 → Wi-Fi | 过渡期不产生目标直连；恢复遵守保护和退避 |
| A5 | IPv4、IPv6、双栈网络 | 两种地址族均无绕过；DNS/域名解析路径纳入观察 |
| A6 | 应用或授权浏览器被排除出 VPN | 系统阻断时应不可直连；不能误显示完整保护 |
| A7 | 测试配置故意将目标路由为 DIRECT | 记录系统阻断无法约束 VPN 内部 DIRECT 的边界；禁止把配置标为可用保护方案 |
| A8 | 启动、前台到期、回前台、连续手动刷新 | 所有入口都遵守暂停与保护状态 |
| A9 | access token 临近到期、响应要求重新认证 | token 请求同样受保护；策略拒绝不盲目重试 |
| A10 | 浏览器授权中断网、回调时断网、重新打开浏览器 | 浏览器系统保护与应用交换保护分别有证据 |
| A11 | 暂停后重启、配置损坏、保存失败 | 符合保守默认值，不静默启用直连 |
| A12 | Debug Q3 授权与本机回调 | 真实远程授权受保护；回环回调正常，不泄露到代理出口 |

证据至少记录：应用版本和 commit、设备/Android 版本、代理客户端和内核版本、保护设置、
脱敏规则、操作时间、观察位置、结果。只看 UI、VPN 图标或 mihomo 连接列表不够证明没有
绕过 mihomo 的直连；需要合适的设备或网关侧观察。确认抓包工具不会占用另一个 VPN 槽位
而替换被测客户端。避免持久保存可识别账号的信息或真实凭据。

“没有观察到直连”只适用于记录中的设备、客户端、配置和测试窗口，不能升级为绝对保证。

## 8. 不采用的做法

- 只检测 VPN 图标或网络接口名，然后展示“安全”。
- 用第三方 IP 查询一次成功就放行所有 Claude 请求；如未来加入 IP 诊断，另行评估隐私和同路由条件。
- 带真实 Claude 凭据进行连通性预检查，或故意在不安全网络测试账号封禁。
- 用默认客户端重试、添加 `DIRECT` 回退、关闭 TLS 校验来提高成功率。
- 自动扫描本机端口、读取其他应用私有配置、读取代理订阅/密码或修改用户 mihomo 配置。
- 为保护本应用另建 VPN、自有代理服务器、远程凭据中转或遥测服务。
- 伪装官方客户端、编造 User-Agent/字段来宣称降低封禁风险。
- 将暂停视为退出登录，删除凭据和快照；把未知 403 写成“账号已封禁”。
- 顺带裁剪 OAuth scopes、改变接口契约或改造 iOS；这些不属于本方案默认实施范围。
- 在静态检查或单测通过后，宣称 Android 防直连或账号安全已经验证。
